Блок-схема: движение данных из 1С в UI

Проект KP · путь после обработки через OData до отображения в интерфейсе

1) 1С OData

Источник документов КП, реквизитов, комментариев, статусов и связанных данных.

2) Backend fetch

Сервис API читает данные из 1С, нормализует поля и собирает строки КП.

3) Обработка правил

Расчет бизнес-статусов, enrichment, подготовка полей для отображения и действий.

4) Оперативный кэш

Данные попадают в память процесса: _cached_rows.

5) Runtime-кэш (файлы)

Снимки записываются в:
data/kp_runtime_cache.json + meta/current.

6) Версионирование + GitHub

Формируются версии в data/runtime_versions, затем снимки и current-pointer публикуются в GitHub.

7) API выдача

Клиент получает данные через /api/kp/all и обновления через /ws/kp.

8) UI Dashboard

Интерфейс рисует карточки, статусы, фильтры и кнопки обработки.

9) Действие пользователя

Кнопки в UI вызывают backend endpoint (например, обработка статуса).

10) PATCH в 1С

Backend отправляет изменения обратно в 1С по OData (комментарии/статусы).

Поток слева направо и сверху вниз: 1С → backend → кэш → API → UI. После действий в UI цикл повторяется через backend обратно в 1С.
